## Prevention and audit scope

1. **Do not write to a repository's default branch** before checking existing Vercel Git connections, production branch rules and automatic deployment; an empty repository is not safe by default. A source-only commit can unexpectedly become a live release.
2. Keep all further work in unmerged Draft branches. Do not merge this partial snapshot or touch `main` again until the owner approves a controlled release plan.
3. Independently check official production aliases and actual page content after deployment changes. A Vercel READY marker can represent a broken site.
4. The recovered site source is text-only and incomplete (missing binary icon/font/native app/API); it is archival evidence, NOT a deployable artifact. Never infer app privacy behavior solely from policy HTML.
5. If URL failures recur, inspect alias target using `get_alias`, compare to known-good CLI deployment and seek explicit approval for changes beyond a corrective rollback.
